# 얼굴 나이 추정 모델 리서치 (노키즈존 필터용)

> 8/18 회의 ④: 노키즈존 구현을 위해 "얼굴 기반으로 나이대를 추정하는 가벼운
> 라이브러리" 검토. 전제 조건: **C 환경(ONNX Runtime C API)**, 저사양 엣지(4200U급),
> 기존 파이프라인에 추가되는 리소스 최소화.

## 결론 요약 (권장 순)

| 순위 | 모델 | 크기 | 입력 | 통합 난이도 | 비고 |
|---|---|---|---|---|---|
| **1** | InsightFace `genderage` | **~1.3MB** | 96×96 얼굴 크롭 | 낮음 (ONNX 단일 파일) | 나이(회귀)+성별. 실사용 검증 많음 |
| 2 | SSR-Net | ~0.3MB | 64×64 얼굴 크롭 | 중간 (Keras→ONNX 변환 필요) | 초경량. 정확도는 1보다 낮음 |
| 3 | MobileNet 기반 UTKFace 파인튜닝 | 3~8MB | 128~224px | 중간 | 연령 구간 분류로 학습하면 노키즈존 용도에 적합 |
| 보류 | MiVOLO | 수십MB (ViT) | 얼굴+전신 | 높음 | SOTA지만 엣지 CPU에 부적합 — 8/3 회의의 "알리바바 추론모델" 결론과 동일 이유 |
| 제외 | FairFace (ResNet34) | ~90MB | 224px | 낮음 | 정확하지만 크기/연산 과다 |

## 1순위 상세: InsightFace genderage.onnx

- buffalo_l/buffalo_sc 모델 팩에 포함된 보조 모델. 입력 96×96 BGR 얼굴 크롭,
  출력 성별 2클래스 + 나이 스칼라.
- **파이프라인 통합 방식** (추가 리소스 거의 0):
  1. 기존 3단계(크롭 정밀 재추론)에서 이미 얼굴 키포인트(눈·코·귀)를 확보한다.
  2. `REASON_KIOSK_ENTER` 트리거 시에만 — 즉 키오스크 앞에 섰을 때 1회 —
     눈·코 키포인트로 얼굴 사각형을 잘라 96×96 letterbox 후 추론.
  3. 나이 < 임계값(점주 설정, 기본 14세) N회 연속이면 `EV_MINOR_SUSPECT` 이벤트.
- 예상 추론 비용: 96×96 CNN 1회 ≈ YOLO 416px 대비 1/50 수준. 키오스크 진입
  시에만 돌므로 상시 부하 없음.
- ORT C API 통합은 기존 `yolo_pose.c`와 동일 패턴 (세션 1개 추가, intra-op 1스레드).

## 정확도 기대치와 정책 설계 (중요)

- 얼굴 나이 추정의 실측 MAE는 좋은 모델도 **±4~6세**. 10대 중후반은
  성인/미성년 경계 판별이 원리적으로 불안정하다.
- 따라서 **"차단"이 아니라 "점주 알림 + 확인"으로 설계**해야 한다
  (8/10 회의 "최종 결정권은 점주에게"와 일치):
  - 추정 나이가 임계값보다 확실히 낮을 때만(예: 추정 ≤ 10세) 알림.
  - 경계 구간은 무시 — 오탐 알림이 반복되면 점주가 기능을 꺼버린다.
- 개인정보: 나이 스칼라만 사용하고 얼굴 이미지는 저장하지 않는다
  (기존 파이프라인의 비식별 원칙 유지).
